# ドラゴンボールMOD (サーバーサイド / Fabric 26.3・26.1)

ドラゴンボール7個とドラゴンレーダーを追加する **サーバー専用MOD** です。
プレイヤー側は **バニラのクライアントのまま接続し、リソースパックをダウンロードするだけ** で遊べます。

- 対応: **Minecraft 26.3** と **26.1 (26.1.2)**。バージョンごとに専用の jar が作られます。
- 旧「Dragon Ball Mod 1.0」(Forge 1.12.2) の考え方とテクスチャを元に、26.x 向けに作り直したものです。
- 仙豆・筋斗雲・防具などは含みません。

> **現在の状況**
> - GitHub Actions で、26.3 用・26.1.2 用の jar の**ビルドが成功することを確認済み**です。
> - ゲーム内での動作は、導入後に「[6. 初回起動と確認](#6-初回起動と確認)」のチェックリストで確認してください。

## 1. 追加されるもの

| もの | 内容 |
|---|---|
| ドラゴンボール 一星球〜七星球 | 各1個ずつ。**銅チェストに入った状態で、地上のランダムな場所**に設置されます |
| ドラゴンレーダー | **一番近いボール**の方向を指します。誰かが持っているボールには反応しません |
| ギャルのパンティ | **頭に被れる装備**。被るとパンツを顔に被った見た目になり (目は足を通す穴から、後頭部・髪は素のまま。リボンは頭頂部)、**かぼちゃと同じように視界が狭くなります** |
| `/db` コマンド | 運営 (OP) 用の管理コマンド |
| 設定ファイル | `config/dragonball.properties` (日本語コメント付き) |

見た目:
- ボール: インベントリ・ホットバーでは平らなアイコン (星の数が見やすい)。手に持ったとき・落としたとき・額縁に入れたときは **丸い立体モデル**
- レーダー: バニラのコンパスと同じ32コマの針。他のプレイヤーのレーダーとは独立して動きます
- パンティ: インベントリでは平らなアイコン (白い下着に赤い小さなリボン)。被ると、頭が「パンツを顔に被った」見た目になる

### ギャルのパンティ (頭装備) の仕様

- 頭の装備スロットに入れると、**パンツを顔に被った見た目** (変態仮面のような被り方) になります。他のプレイヤーからも同じ見た目で見えます。
  - **頭頂部:** パンティの腰のゴムが、頭頂部の**前半分**をまたぎます。**ゴムの中央にある赤い小さなリボン**は、
    アイコンのパンティと同じ位置・同じ形のままで、被ると頭頂部の中央に来ます (結び目の側が顔の側)。後ろ半分は素の髪です。
  - **額:** ゴムではなく、パンツ本体の布です。
  - **目:** 足を通す穴が目の穴になり、**眉・目・目の下の頬**が見えます。
  - **鼻・口・あご:** 目の穴以外の顔は布で覆われ、あごに向かって細くなります。
  - **側面:** 布が頬から耳の手前まで回り込みます。**耳より後ろは素の頭**です。
  - **後頭部:** パンツはかからず、**普通の後頭部**が見えます。
- 布がない部分はすべて透明です。**髪型・肌・後頭部は、各プレイヤー自身のスキンがそのまま見えます** (アカウントごとに違う見た目になります)。
- 被っている間は、**かぼちゃを被ったときと同じ仕組みで視界が狭くなります** (一人称視点のみ。目の穴の形に見える)。
  外せば元に戻ります。
- 右クリックで装備できます。頭に被っているものがあれば入れ替わります。
- 体の見た目 (スキン全体) は変わりません。変わるのは**頭の部分だけ**です。
  バニラのクライアントでは、サーバー側の装備でプレイヤーのスキン全体を差し替えることはできないためです。

## 2. アイテムIDとコマンド

### アイテムID

| アイテム | ID | スタック |
|---|---|---|
| 一星球 | `dbzmod:dragonball_1` | 1 |
| 二星球 | `dbzmod:dragonball_2` | 1 |
| 三星球 | `dbzmod:dragonball_3` | 1 |
| 四星球 | `dbzmod:dragonball_4` | 1 |
| 五星球 | `dbzmod:dragonball_5` | 1 |
| 六星球 | `dbzmod:dragonball_6` | 1 |
| 七星球 | `dbzmod:dragonball_7` | 1 |
| ドラゴンレーダー | `dbzmod:dragon_radar` | 1 |
| ギャルのパンティ | `dbzmod:gal_panties` | 64 |

### 渡す・消すときのコマンド

| やりたいこと | コマンド | 備考 |
|---|---|---|
| パンティを渡す | `give <プレイヤー> dbzmod:gal_panties [個数]` | 個数は省略可 (最大64)。右クリックまたはドラッグで頭に装備 |
| レーダーを渡す | `give <プレイヤー> dbzmod:dragon_radar` | `/db radar [プレイヤー]` でも可 |
| **ボールを渡す** | **`db give <プレイヤー> <1-7>`** | **`give` は使わない** (下の注意を参照) |
| ボールを消す | `clear <プレイヤー> dbzmod:dragonball_N 1` | N は 1〜7 |
| 持っている個数を調べる | `clear <プレイヤー> dbzmod:dragonball_N 0` | 消さずに個数だけ返す |
| 7個を新しい場所へ散らす | `db respawn all` | 願い事のあとなどに |

> ⚠️ **ボールに `give` を使わないでください。**
> `give` で出したボールには「個体ID」が付いていないため、整合性チェックが「古い複製」と判断して、
> **最大5秒ほどで削除します**。ボールを渡すときは、必ず `/db give` を使ってください
> (既存のボールを移す形になるので、複製にもなりません)。

### 外部ツール (RCON・コンソール・Bot など) から使う場合

先頭の `/` は付けずに送れます。OP 権限が必要なのは `db ...` コマンドで、コンソールや RCON は権限を満たしています。

```
clear Steve dbzmod:dragonball_1 1
db respawn all
db give Steve 4
db status
```

- ボールを消したあと何も送らなくても、**約15〜20秒後に新しいランダム位置へ自動で再配置**されます。
  すぐ散らしたいときは `db respawn all` を送ってください。
- `clear` はプレイヤーがオフラインだと失敗します。取り残しは `db respawn all` で一掃できます
  (古い個体IDのボールは、次の整合性チェックで削除されます)。
- `db respawn` は遠い地点の地形を生成するため、7個まとめると一瞬サーバーが重くなることがあります。

## 3. 必要なもの

### サーバー (`mods` フォルダ)
既存の `fabric-api`, `lithium`, `krypton`, `NoChatReports` はそのままで構いません。
追加するのは、**このMODの jar** と **Polymer** の2つです。

| サーバーの Minecraft | このMODの jar | Polymer | Fabric API |
|---|---|---|---|
| **26.3** | `dbzmod-1.0.0-mc26.3.jar` | `polymer-bundled-0.18.2+26.3.jar` | `0.161.0+26.3` |
| 26.1 / 26.1.1 / 26.1.2 | `dbzmod-1.0.0-mc26.1.2.jar` | `polymer-bundled-0.16.5+26.1.2.jar` | `0.155.3+26.1.2` 以降 |

- Polymer は Modrinth の「Polymer」から、`polymer-bundled` を入手してください。
- Fabric API は、**サーバーの Minecraft に合った版**にしてください。

> ⚠️ **jar は Minecraft のバージョンごとに別物です。** Minecraft 本体の内部は版ごとに変わるため、
> 26.1 用の jar を 26.3 のサーバーに入れる (またはその逆) と、動かなかったり、起動時にエラーになったりします。
> サーバーを更新するときは、**jar と Polymer を新しい版用に入れ替えてください。**
> リソースパックは両方で共通です。

`lmmediatelyFast` (ImmediatelyFast) はクライアント用MODです。サーバーには不要です。

### プレイヤー側
サーバーと同じバージョンのバニラのクライアントと、リソースパック (自動ダウンロード) だけです。MODは不要です。

## 4. ビルドと公開 (すべて自動)

26.x のビルドには JDK 25 が必要ですが、GitHub 上でビルドさせれば自分のPCに入れる必要はありません。
**ファイルをアップロード (push) するだけで、ビルドから Releases への公開まで自動で行われます。**

1. GitHub で新しいリポジトリを作る (**Public** にしてください。理由は[5章](#5-リソースパックの配信))
2. このフォルダの中身を、そのままリポジトリ (`main` ブランチ) へアップロードする
   - Web画面の「Add file → Upload files」にドラッグ&ドロップで構いません。
   - **`.github` フォルダも忘れずに含めてください** (隠しフォルダ扱いで見落としやすい)。
3. 「Actions」タブで `build` が自動で走ります (5分前後)。26.3 用と 26.1.2 用が**別々に**ビルドされます。
4. 緑のチェックが付いたら、**Releases** に「Build #N」が自動で公開されます。添付されるファイル:
   - `dbzmod-1.0.0-mc26.3.jar` … 26.3 用 MOD
   - `dbzmod-1.0.0-mc26.1.2.jar` … 26.1.2 用 MOD
   - `dbzmod-resourcepack.zip` … リソースパック (両方で共通)
5. 手でリリースを作る必要はありません。ファイルを更新して push するたびに、新しい「Build #N」が増えます。
   古いものは Releases 画面から削除して構いません。

補足:
- 片方の jar だけ添付されている場合は、もう片方のビルドが失敗しています。使わない方なら問題ありません。
- `Actions` に古い `release` ワークフローが残っている場合は、`.github/workflows/release.yml` を削除してください。

## 5. リソースパックの配信

GitHub の Releases を、リソースパックの配信先として使います。

1. 最新の「Build #N」の説明欄に、**そのまま貼れる値 (URL と SHA-1)** が自動で書かれています。
2. サーバーの `server.properties` に貼り付けて保存し、サーバーを再起動します。

```properties
resource-pack=https://github.com/<ユーザー名>/<リポジトリ名>/releases/download/build-N/dbzmod-resourcepack.zip
resource-pack-sha1=<リリースの説明欄に書かれた値>
require-resource-pack=true
# 任意: パックの承認画面に出る説明文
resource-pack-prompt=ドラゴンボール用のリソースパックです。必ず「はい」を選んでください。
```

- リポジトリを **Public** にするのは、プレイヤーのゲームが認証なしでダウンロードできる必要があるためです。
- **リソースパックの中身が前回と同じなら、SHA-1 も前回と同じ**になります。
  MODのコードだけを直した場合は、`server.properties` を書き換える必要はありません
  (古いビルドの URL がそのまま使えます。そのリリースを削除しない限り有効です)。
- リソースパック (`resourcepack/` の中身) を変更したときだけ、新しい URL と SHA-1 に更新してください。
  SHA-1 を更新しないと、プレイヤー側に古いパックが残ります。

## 6. 初回起動と確認

1. `mods` に `dbzmod-*.jar` と Polymer を入れて起動します。
2. 初回に `config/dragonball.properties` が自動生成され、ボール7個が**銅チェストに入って**ランダムな場所に置かれます。
   (地形の生成が走るため、初回だけ少し時間がかかります)
3. 起動ログに、次の行が出ることを確認します。
   - `ドラゴンボールMODを開始しました。`
   - `番ボールを配置しました` (7行)
4. OP でサーバーに入り、試します。

```
/db status            7個の座標が出る
/db tp 1              一星球のチェストへ移動
/db radar             レーダーを受け取る
give @s dbzmod:gal_panties
```

確認チェックリスト:
- [ ] ボールが銅チェストに入っている (バニラクライアントで開ける)
- [ ] ボールを手に持つと、丸い立体モデルが見える (インベントリでは平らなアイコン)
- [ ] 名前が「一星球」などの日本語で表示される
- [ ] レーダーの針が、最寄りのボールの方向を指す
- [ ] 他の人がボールを持っている間、レーダーはそのボールに反応しない
- [ ] パンティのアイコンが「白いパンティに赤いリボン」で表示される
- [ ] パンティを頭に被ると、パンツを顔に被った見た目になる (F5 の三人称視点や、別のプレイヤーから見て確認)
  - 目が穴から見え、鼻・口・あごは布で覆われている
  - 頭頂部の前半分にゴムの帯があり、中央に赤い小さなリボンが乗っている (アイコンと同じ形)
  - 後頭部と、頭頂部の後ろ半分は普通の髪が見える
  - 髪型や肌が、自分のスキンのままになっている
- [ ] 被っている間、一人称視点で視界が狭くなる (かぼちゃと同じ)

## 7. 設定ファイル

`config/dragonball.properties` に、日本語の説明付きで書かれています。主な項目:

| 項目 | 初期値 | 意味 |
|---|---|---|
| `spawn.center_x` / `center_z` | 0 / 0 | 配置範囲の中心座標 |
| `spawn.min_radius` / `max_radius` | 500 / 5000 | 中心からこの距離の輪の中にランダム配置 |
| `spawn.min_distance_between_balls` | 300 | ボール同士の最低距離 |
| `spawn.max_attempts` | 80 | 置ける場所を探す最大回数 (見つからないときは増やす) |
| `spawn.avoid_ocean` / `avoid_river` | true | 海・川には置かない |
| `spawn.waxed_chest` | true | ワックス掛け済みの銅チェスト (錆びない) |
| `radar.update_interval_ticks` | 20 | レーダーが最寄りを再計算する間隔 |
| `radar.max_range_blocks` | 0 | レーダーの反応距離 (0 = 無制限) |
| `audit.interval_ticks` | 100 | 整合性チェックの間隔 (100tick = 5秒) |
| `audit.lost_grace_audits` | 3 | 何回連続で見つからなければ「消失」とみなすか |
| `log.events` | true | ボールの出入りをサーバーログに記録 |
| `announce.pickup` | false | ボール入手を全員にチャットで告知 |

変更後は `/db reload` で反映されます。
ただし、**すでに置かれたボールは動きません**。動かすには `/db respawn` を使ってください。

## 8. 運営用コマンド `/db`

OP (権限レベル2以上) 専用です。

| コマンド | 内容 |
|---|---|
| `/db status` | 7個すべての状態・座標・所持者を表示 |
| `/db locate <1-7>` | 指定ボールの位置を表示 |
| `/db tp <1-7>` | 指定ボールの位置へテレポート |
| `/db give <プレイヤー> <1-7>` | ボールを **既存のものごと移して**付与 (複製にならない) |
| `/db radar [プレイヤー]` | ドラゴンレーダーを付与 |
| `/db respawn <1-7\|all>` | 新しいランダム位置へ再配置 (旧実体は削除される) |
| `/db return <1-7>` | 最初に置かれたチェストへ戻す |
| `/db sethere <1-7>` | 今いる場所へ銅チェストごと移動 |
| `/db audit` | 整合性チェックを今すぐ実行 |
| `/db reload` | 設定ファイルを再読み込み |
| `/db config` | 現在の主な設定値を表示 |

ドラゴンレーダーのレシピ: 鉄インゴット4個を十字に置き、中央にエンダーパール。

## 9. 仕組みと制限 (「消えない・重複しない」について)

**ボール1個ごとに「個体ID」を持たせ、ワールドデータ (`dragonball_state.json`) の台帳と照合しています。**
5秒ごとに、ロード済みの範囲にあるプレイヤーの所持品・エンダーチェスト・コンテナ・落下アイテム・額縁・モブの手持ちを調べます。

| 状況 | 動き |
|---|---|
| 重複 | 台帳にない個体IDのボール (コピーされたもの) や、同じ番号の余剰分を見つけて削除 |
| 消失 | 虚空に落ちた、削除された、などで**確実に消えたと分かった場合のみ**、新しいランダム位置へ再配置 |
| 読み込まれていないチャンク内 / 持ち主がオフライン | 「消失」とは判断しない (そのまま待つ) |
| 落ちたボール | 時間で消えない。炎・溶岩に耐える。無敵のため、爆発・サボテンでも壊れない |
| シュルカーボックス・バンドル | 格納不可 (中身を追跡できなくなるため) |

レーダーの動き:
- 追跡するのは、**ワールド上にあるボール** (チェスト・落ちているアイテムなど) です。プレイヤーの所持品とエンダーチェストの中は追跡しません。
- オーバーワールド以外にいるときや、追跡できるボールがないときは、針がランダムに回ります。

防げないもの:
- サーバー外でのワールドファイル編集、MODを経由しない手段 (`give` など)
- 虚空に落ちたボールは、消えてから**およそ15〜20秒**で新しい場所に再配置されます (その間は存在しません)
- 銅チェストの横で銅ゴーレムを作ると、ボールを木のチェストへ運ぶことがあります (消えはしません)

台帳 (`<ワールド>/dragonball_state.json`) について:
- ワールドのバックアップに含めてください。
- **このファイルを削除すると、全ボールが新しい個体IDで再生成され、既存のボールは古い複製として削除されます。**

整合性が心配なときは、`/db audit` と `/db status` を使ってください。

## 10. うまくいかないとき

### Releases に何も出ない / ビルドが赤い

- Actions の実行ページで、`release` の処理のログを開き、`Error:` の行を確認してください。
- `Resource not accessible by integration` と出る場合は、リポジトリの **Settings → Actions → General → Workflow permissions** を
  「Read and write permissions」に変えてください。
- `main` (または `master`) ブランチに push していないと、ビルド自体が始まりません。
- ビルドが失敗した場合は、`error:` と書かれた行の前後をコピーして共有してください。
  Minecraft 26.x は版ごとに内部の名前が変わるため、新しい版では修正が必要になることがあります。

### 起動時にエラーが出る

- Polymer を入れ忘れていないか (`polymer-core が見つからない` と出る)
- Fabric API・Polymer・このMODの jar が、**サーバーの Minecraft と同じ版用**か
- サーバーの Java が **25 以上**か

### ボールが見えない・名前が「トライアルキー」になる

- リソースパックが読み込まれていない可能性があります。`server.properties` の URL と SHA-1 を確認してください。
- 名前だけは、パックが無くても日本語で表示される作りです。

### パンティを被っても見た目が変わらない・視界が狭くならない

- リソースパックが読み込まれていない可能性があります。`server.properties` の URL と SHA-1 を確認してください。
- 起動ログに「視界オーバーレイを設定できませんでした」と出ている場合は、そのメッセージを共有してください (視界だけが効かない状態です)。
- 目の穴の位置が、自分のスキンの目とずれる場合は、`tools/make_panties_worn_texture.py` の `FRONT` の穴の位置を直せます。
- 視界の制限は**一人称視点のみ**です (かぼちゃと同じ)。

### ボールを渡したのに消えた

- `give` で出していませんか。必ず `/db give` を使ってください ([2章](#2-アイテムidとコマンド)参照)。

### ボールが置かれない

- ログに「置ける場所が見つかりませんでした」と出る場合は、`spawn.max_attempts` を増やすか、範囲を広げてください。

## 11. 開発メモ

### フォルダ構成

```
build.gradle / gradle.properties   ビルド設定 (Minecraft・Fabric・Polymer のバージョン)
src/main/java/...                  MOD本体
src/main/resources/                fabric.mod.json, レシピ
resourcepack/                      リソースパック (これを zip にして配信)
tools/generate_pack.py             モデル・アイテム定義・言語ファイルの生成スクリプト
tools/make_panties_texture.py      パンティのアイコンの生成スクリプト
tools/make_panties_worn_texture.py 被ったときの顔のテクスチャの生成スクリプト
.github/workflows/build.yml        自動ビルドと Releases への自動公開
```

### 別のバージョンでビルドする

`gradle.properties` の `minecraft_version` / `fabric_api_version` / `polymer_version` / `minecraft_dep` を書き換えます
(ファイル冒頭の表に 26.3 と 26.1.2 の値があります)。
GitHub Actions で自動ビルドする版を増やすときは、`build.yml` の `matrix` に1項目足します。

### 見た目を変える

- ボールの大きさ・手に持ったときの位置は、`tools/generate_pack.py` の `RADIUS` と `DISPLAY` を調整して `python3 tools/generate_pack.py` を実行します。
- パンティのアイコンは、`tools/make_panties_texture.py` の色や形を直して実行します。
- 被ったときの顔は、`tools/make_panties_worn_texture.py` を直して実行します。各面を文字の並び (`W`=布、`.`=透明など) で定義しているので、穴の位置や、布の範囲もここで変えられます。
- 被ったときの視界の形は、`resourcepack/assets/dbzmod/textures/misc/pantiesblur.png` を差し替えます (透明な部分が見える範囲です。かぼちゃの視界と同じ形式)。
- どちらも、実行後に push すれば自動でビルド・公開されます (リソースパックの SHA-1 が変わります)。

### バージョン間の違いを吸収している箇所

- `Compat.java`: エンティティを無敵にするメソッド名が、26.1 と 26.3 で違うため。
- `BallManager.copperChestBlock()`: 銅チェストのブロックの持ち方が違うため、登録IDで取得。
- `Compat.headEquippable()`: 頭装備 (見た目の指定と視界オーバーレイ) の作り方を、版が違っても通るように組み立てる。
