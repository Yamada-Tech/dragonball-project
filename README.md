# ドラゴンボールMOD (サーバーサイド / Fabric 26.3・26.1)

ドラゴンボール7個とドラゴンレーダーを追加する **サーバー専用MOD** です。
プレイヤー側は **バニラのクライアントのまま接続し、リソースパックをダウンロードするだけ** で遊べます。

旧「Dragon Ball Mod 1.0」(Forge 1.12.2) の考え方とテクスチャを元に、26.x向けに作り直したものです。
**Minecraft 26.3 と 26.1 (26.1.2) の両方に対応**しており、それぞれ専用の jar が作られます (理由は下の注意書き参照)。
仙豆・筋斗雲・防具などは含みません。

> ⚠️ **このプロジェクトは、作成した環境でコンパイル・実機テストをしていません。**
> 26.1 / 26.3 の公式ソース (Fabric API / Polymer) を読んでAPI名を合わせています。
> **26.1.2 用は、実際にビルドが成功することを確認済み**です (実機での動作は未確認)。
> **26.3 用は、まだビルドしていません**。初回ビルドでエラーが出る可能性があります。その場合は「[8. うまくいかないとき](#8-うまくいかないとき)」を参照してください。

---

## 1. 何が追加されるか

| もの | 内容 |
|---|---|
| ドラゴンボール 一星球〜七星球 | 各1個ずつ。**銅チェストに入った状態で地上のランダムな場所に設置**されます |
| ドラゴンレーダー | **一番近いボール**の方向を指します。誰かが持っているボールには反応しません |
| ギャルのパンティ (`dbzmod:gal_panties`) | 見た目だけのアイテム (効果なし)。`/give` で渡せます。スタック64。ボールの管理・整合性チェックの対象外 |
| `/db` コマンド | 運営(OP)用の管理コマンド |
| 設定ファイル | `config/dragonball.properties` (日本語コメント付き) |

見た目:
- インベントリ・ホットバーでは平らなアイコン (星の数が見やすい)
- 手に持ったとき・落としたとき・額縁に入れたときは **丸い立体モデル**

## 2. 必要なもの

### サーバー (`mods` フォルダ)
既存の `fabric-api`, `lithium`, `krypton`, `NoChatReports` はそのままで構いません (Fabric API は **サーバーの Minecraft に合った版**にしてください)。
追加するのは次の2つです。

| サーバーの Minecraft | このMODの jar | Polymer (Modrinth の「Polymer」から `polymer-bundled`) |
|---|---|---|
| **26.3** | `dbzmod-1.0.0-mc26.3.jar` | `polymer-bundled-0.18.2+26.3.jar` |
| 26.1 / 26.1.1 / 26.1.2 | `dbzmod-1.0.0-mc26.1.2.jar` | `polymer-bundled-0.16.5+26.1.2.jar` |

> ⚠️ **jar は Minecraft のバージョンごとに別物です。** Minecraft 本体の内部は版ごとに変わるため、
> 26.1 用の jar を 26.3 のサーバーに入れる (またはその逆) と、動かなかったり起動時にエラーになったりします。
> サーバーを更新するときは、**jar と Polymer を新しい版用に入れ替えてください**。
> リソースパックは両方で共通です。

> `lmmediatelyFast` (ImmediatelyFast) はクライアント用MODです。サーバーには不要です。

### プレイヤー側
- サーバーと同じバージョンのバニラのクライアントと、リソースパック (自動ダウンロード) だけです。MODは不要です。

## 3. ビルドと公開 (すべて自動 / PCにJDKは不要)

26.x のビルドには JDK 25 が必要ですが、GitHub のサーバー上でビルドさせれば自分のPCに入れる必要はありません。
**ファイルをアップロード (push) するだけで、ビルドから Releases への公開まで自動で行われます。**

1. GitHub で新しいリポジトリを作る (**Public** にしてください。理由は手順4)
2. このフォルダの中身を、そのままリポジトリ (main ブランチ) へアップロードする
   - Web画面の「Add file → Upload files」で、フォルダの中身をドラッグ&ドロップでも構いません。
   - `.github` フォルダも忘れずに含めてください (隠しフォルダ扱いで見落としやすい)。
3. 「Actions」タブの `build` が自動で走ります (5分前後)。26.3 用と 26.1.2 用が**別々に**ビルドされます。
4. 緑のチェックが付いたら、リポジトリの **Releases** に「Build #N」が自動で公開されています。次のファイルが添付されます。
   - `dbzmod-1.0.0-mc26.3.jar` … 26.3 用 MOD
   - `dbzmod-1.0.0-mc26.1.2.jar` … 26.1.2 用 MOD
   - `dbzmod-resourcepack.zip` … リソースパック (両方で共通)
   - 片方の jar だけ添付されている場合は、もう片方のビルドが失敗しています。使わない方なら問題ありません。
5. 手でリリースを作る必要はありません。ファイルを更新して push するたびに、新しい「Build #N」が増えます。
   古いものは、Releases 画面から削除して構いません。

> `Actions` で `release` という名前の古いワークフローが残っている場合は、
> `.github/workflows/release.yml` を削除してください (今は使いません)。

## 4. リソースパックの配信 (GitHub を使う)

1. 最新の「Build #N」リリースの説明欄に、**そのまま貼れる `server.properties` の値 (URL と SHA-1)** が自動で書かれています。
2. サーバーの `server.properties` にその3行を貼り付けて保存し、サーバーを再起動します。

```properties
resource-pack=https://github.com/<ユーザー名>/<リポジトリ名>/releases/download/build-N/dbzmod-resourcepack.zip
resource-pack-sha1=<リリースの説明欄に書かれた値>
require-resource-pack=true
```

- リポジトリを Public にするのは、プレイヤーのゲームが認証なしでダウンロードできる必要があるためです。
- **リソースパックの中身が前回と同じなら、SHA-1 も前回と同じになります。**
  MOD のコードだけを直した場合は、`server.properties` を書き換える必要はありません。古いビルドの URL をそのまま使えます
  (そのリリースを削除しない限り有効です)。
- リソースパック (`resourcepack/` の中身) を変更したときだけ、新しい URL と SHA-1 に更新してください。
  SHA-1 を更新しないと、プレイヤー側に古いパックが残ります。

## 5. 初回起動と確認

1. `mods` に `dbzmod-*.jar` と Polymer を入れて起動します。
2. 初回に `config/dragonball.properties` が自動生成され、ボール7個が **銅チェストに入って** ランダムな場所に置かれます。
   (地形の生成が走るため、初回だけ少し時間がかかります)
3. OPで入り、次を確認します。

```
/db status            ← 7個の座標が出る
/db tp 1              ← 一星球のチェストへ移動
/db radar             ← レーダーを受け取る
```

確認チェックリスト:
- [ ] ボールがチェストに入っている (バニラクライアントで開ける)
- [ ] ボールを手に持つと、丸い立体モデルが見える (インベントリでは平らなアイコン)
- [ ] 名前が「一星球」などの日本語で表示される
- [ ] レーダーの針が、最寄りのボールの方向を指す
- [ ] 他の人がボールを持っている間、レーダーはそのボールに反応しない

## 6. 設定 (`config/dragonball.properties`)

ファイル内に日本語の説明が書かれています。主な項目:

| 項目 | 初期値 | 意味 |
|---|---|---|
| `spawn.center_x` / `center_z` | 0 / 0 | 配置範囲の中心座標 |
| `spawn.min_radius` / `max_radius` | 500 / 5000 | 中心からこの距離の輪の中にランダム配置 |
| `spawn.min_distance_between_balls` | 300 | ボール同士の最低距離 |
| `spawn.avoid_ocean` / `avoid_river` | true | 海・川には置かない |
| `spawn.waxed_chest` | true | ワックス掛け済みの銅チェスト (錆びない) |
| `radar.update_interval_ticks` | 20 | レーダーが最寄りを再計算する間隔 |
| `radar.max_range_blocks` | 0 | レーダーの反応距離 (0 = 無制限) |
| `audit.interval_ticks` | 100 | 整合性チェックの間隔 (5秒) |
| `announce.pickup` | false | ボール入手を全員にチャットで告知 |

変更後は `/db reload` で反映されます (**すでに置かれたボールは動きません**。動かすには `/db respawn`)。

## 7. 運営用コマンド `/db` (OP専用)

| コマンド | 内容 |
|---|---|
| `/db status` | 7個すべての状態・座標・所持者を表示 |
| `/db locate <1-7>` | 指定ボールの位置を表示 |
| `/db tp <1-7>` | 指定ボールの位置へテレポート |
| `/db give <プレイヤー> <1-7>` | ボールを **既存のものごと移して** 付与 (複製にならない) |
| `/db radar [プレイヤー]` | ドラゴンレーダーを付与 (レシピは鉄インゴット4個を十字+中央エンダーパール) |
| `/db respawn <1-7\|all>` | 新しいランダム位置へ再配置 (旧実体は削除される) |
| `/db return <1-7>` | 最初に置かれたチェストへ戻す |
| `/db sethere <1-7>` | 今いる場所へ銅チェストごと移動 |
| `/db audit` | 整合性チェックを今すぐ実行 |
| `/db reload` | 設定ファイルを再読み込み |
| `/db config` | 現在の主な設定値を表示 |

## 8. うまくいかないとき

### ビルドが失敗する (GitHub Actions が赤い ✕)
Actions のページでログを開き、`error:` と書かれた行の前後をコピーして共有してください。
Minecraft 26.x は版ごとに内部の名前が変わることがあり、次のような箇所は修正が必要になる可能性があります
(いずれも1〜2行の修正で済む想定です)。

| 場所 | 想定されるエラー |
|---|---|
| `BallManager` : `lvl.isPositionEntityTicking(...)` | メソッド名の違い (代わりに `lvl.hasChunk(...)` でも動くが精度が下がる) |
| `BallManager` : `Blocks.WAXED_COPPER_CHEST` / `Blocks.COPPER_CHEST` | ブロック名の違い |
| `BallManager` : `getHeightmapPos(...)` | 引数の違い |
| `DbzCommands` : `player.teleport(new TeleportTransition(...))` | 引数の違い |
| `BallItem` : `canFitInsideContainerItems()` | 無い場合は単に効果がないだけ (エラーにはならない) |

別のバージョン (26.2 など) 向けに自分でビルドしたい場合は、`gradle.properties` の
`minecraft_version` / `fabric_api_version` / `polymer_version` / `minecraft_dep` を書き換えます
(ファイル冒頭の表に 26.3 と 26.1.2 の値があります)。

### 起動時にエラー
- Polymer を入れ忘れていないか (`polymer-core が見つからない` と出る)
- Fabric API・Polymer・このMODの jar が、**サーバーの Minecraft と同じ版用**か

### ボールが見えない・名前が「トライアルキー」になる
- リソースパックが読み込まれていない可能性があります。`server.properties` の URL と SHA-1 を確認してください。
- 名前だけは、パックが無くても日本語で表示される作りです。

## 9. 仕組みと制限 (「消えない・重複しない」について)

**ボール1個ごとに「個体ID」を持たせ、ワールドデータ (`dragonball_state.json`) の台帳と照合しています。**
5秒ごとに、ロード済みの範囲にあるプレイヤーの所持品・エンダーチェスト・コンテナ・落下アイテム・額縁・モブの手持ちを調べます。

- **重複**: 台帳にない個体IDのボール (コピーされたもの) や、同じ番号の余剰分を見つけて削除します。
- **消失**: 虚空に落ちた、削除された、などで **確実に消えたと分かった場合のみ**、新しいランダム位置へ再配置します。
  - 読み込まれていないチャンクの中にある場合や、持ち主がオフラインの場合は「消失」とは判断しません。
- **保護**: 落ちたボールは時間で消えず、炎・溶岩に耐え、落ちた状態では無敵になるため、爆発・サボテンなどでも壊れません。
- **シュルカーボックス・バンドルへの格納は不可** にしています (中身を追跡できなくなるため)。

次のものは防げません。
- サーバー外でのワールドファイル編集、`/give` などMODを経由しない手段
- 虚空に落ちたボールは、消えてから、およそ15〜20秒で新しい場所に再配置されます (その間は存在しません)
- 銅チェストの横で銅ゴーレムを作ると、ボールを木のチェストへ運ぶことがあります (消えはしません)

整合性が心配なときは `/db audit` と `/db status` を使ってください。

- ボールとレーダーのテクスチャは、旧MOD「Dragon Ball Mod 1.0」(作者 Exline) のものを流用しています。
